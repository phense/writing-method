# Implementation Plan: Narrated presentation videos

## Stable work ID

- Feature ID: `WM-001`
- Specification: `docs/specs/WM-001-presentation-video/spec.md` (approved by
  the maintainer on 2026-11-13)
- Artifact path: `docs/specs/WM-001-presentation-video/plan.md`

## Summary

Add three method skills, one shared speech guide, one project template with
its tools, two credential examples and one playbook template. The template is
copied into a target project once per video. Its tools are small programs with
one job each; every numeric gate reads its limit from the video profile.

The main technical change against the eleven existing projects: **one
timeline implementation**. Until now the timing rule existed twice (in the
composition and in the check-still tool) and ignored silence inside the sound
files. A single tool now writes `timeline.json`; the composition, check
stills, captions and measurements all read it. Measured defaults are in
[research.md](research.md).

## Technical context

- Languages and versions: Python 3.11 standard library for all tools and
  tests (no new Python dependency). The template uses Node 20 or newer with
  Remotion 4 and TypeScript, as in the existing projects.
- Relevant components and paths: `skills/`, `shared/media/`,
  `shared/policies/lifecycle-handoffs.md`, `templates/presentation-video/`,
  `env/`, `method.json`, `tests/`, `evals/`, `README.md`, `docs/usage.md`.
- Storage and external systems: Azure AI Speech (HTTPS, key in an env file),
  ElevenLabs (connector in the assistant session), a speech recognizer for
  read-back (command named in the profile), `ffmpeg`/`ffprobe`, optionally a
  render machine reached over SSH.
- Constraints and scale: videos up to 45 minutes, about 300 narration lines;
  one request per line on the Azure path; free-tier rate limits.

## Compatibility boundaries

- Preserved behavior: the ten writing skills and all Core files. The
  narration data keeps its existing fields (`text`, `speak`, `show`, `min`),
  so an existing project can adopt the template tools by adding a profile.
- Migration and rollback: no migration. Rollback removes the added paths and
  reverts `method.json`, the handoff graph, the inventory test and the
  documentation.
- Deployment or versioning boundary: version 0.2.0 in all six places listed
  in research R-5. Release and reinstallation on the hosts stay a maintainer
  step.

## Design decisions

| ID | Decision | Reason | Alternative rejected |
|---|---|---|---|
| D-01 | Tools live in the template and are copied into the video project | A video project must render months later without the plugin version that created it | Tools inside the plugin only: later plugin changes would alter old videos |
| D-02 | `timeline.json` is generated by one Python tool and read by everything else | Removes the duplicated timing rule; makes captions and measurements trivial | Keep timing in the composition code: stays duplicated |
| D-03 | Pause accounting by measured silence, files untouched | Exact audible pause, provider-independent, no re-encoding of speech | Trim silence from files: destructive, re-encodes |
| D-04 | Profile and pronunciation list are JSON | Readable by Python and Node without dependencies | YAML: needs a parser |
| D-05 | Two profile levels: project-wide `video-profile.json` and per-video `video.json` | House choices once, video facts per video | One file per video: house choices drift |
| D-06 | Script is two files: `script/script.md` for people (audience, goal, chapters, sources, evidenced/approximated/invented) and `src/narration.json` for machines | Reviewable prose and stable machine input; checks cross-validate both | One Markdown file parsed for narration: fragile |
| D-07 | Read-back recognition is a configurable command producing word timings; the connector's transcription is the alternative | No bundled recognizer; projects already differ | Bundle a recognizer: heavy dependency |
| D-08 | Provider settings are probed: each setting is voiced twice with and twice without, and counts as effective only beyond the spread | Research R-3: a setting was trusted for weeks without effect | Trust provider documentation |
| D-09 | ElevenLabs is a procedure in the skill plus a splitting tool; no key | Maintainer decision; connector spends credits per call | API client with stored key |
| D-10 | Missing-character defects stay a visual check on stills; the template states its fonts' coverage and warns on on-screen characters outside it | A reliable automatic glyph check needs a font library | Add a font-parsing dependency |

## Tests

- Targeted (`tests/test_presentation_video.py`, no media tools): timeline
  arithmetic including silence accounting, minimum slot, scene pauses and
  chapter marks; caption output; script check for each rule in FR-001 to
  FR-006 and the length rule (AC-017); pronunciation merge and conflicts;
  profile validation; multilingual check (AC-016); cache naming; retry and
  budget handling against a fake provider (AC-005); credential check failures
  without network (AC-010).
- Contract: narration fixtures taken from an existing project load unchanged;
  manifest, timeline and measurement files validated against the documented
  fields; skill inventory, handoff graph and trigger matrix assertions.
- Integration (skipped without `ffmpeg`): generated tones with known silence
  give the expected audible pause (AC-013); a generated clip with wrong
  loudness fails the delivery check (AC-007); splitting a generated take at
  word boundaries; the seeded-defect project yields its four automatic
  findings.
- Host evaluation: trigger cases for the three skills and the negative cases
  (AC-012); the fifth seeded defect (missing character) is found in the still
  inspection.
- End to end (once, recorded as rehearsal evidence): sample video from the
  template, voiced with Azure, stills, render, measurements, captions; one
  scene voiced through the ElevenLabs connector and split.
- Migration or rollback: one existing project is run with the new tools
  using configuration changes only; its measured pause is compared before and
  after.
